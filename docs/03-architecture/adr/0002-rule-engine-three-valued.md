# ADR-0002 — AI 추출·설명과 규칙 평가를 분리, PASS/FAIL/UNKNOWN 사용

- 상태: `TARGET-DESIGN` · 최초 기록: 2026-11-18 (제공된 v7/업무 정의를 반영한 **팀 검토용 재구성**)
- 결정 주체: 프로젝트 팀(승인자/승인일 미입력). 이 문서는 라이선스/성능·실배포 검증 증거가 아님.
- 연결 요구사항/근거: `EV-04, BR-B01, BR-B02, BR-B03, BR-B04, BR-B05, BR-B06, BR-B07, BR-B08, BR-B09, FR-B02, FR-B03, FR-B04`

## 맥락 — 문제가 무엇이고 왜 결정이 필요한가

학생 소득·학적이 없거나 공고 문장이 애매한데 LLM이 그럴듯한 합격 여부를 만들어내는 위험이 있다.

## 선택한 방향(팀 v7/업무 설계의 목표)

AI는 조건 후보 추출·설명·초안 담당. 검증된 구조화 규칙을 Rule Engine이 3값 AST로 계산. 설명은 계산 결과를 덮어쓰지 못한다.

## 검토해야 할 대안(비교 목록)

- LLM이 직접 가능/불가 반환
- 2값 boolean + null default false
- 규칙을 React 컴포넌트마다 분산

**선택 기준:** 도메인 정확성·학생 경험·작업 유실 위험·현재 팀 인력과 운영 부담·교수님의 대규모 가정. 대안이 정량 비교되었다는 주장은 하지 않는다.

## 얻는 것

입력이 같으면 재현 가능한 결과, UNKNOWN와 FAIL 구별, 근거·사유별 테스트

## 감수할 대가 — 단점도 기록

AST 모델과 Evidence 연결이 필요; 미확정이 많아 화면이 복잡해짐; OR/예외는 추가 설계·테스트

## 무엇을 검증해야 이 결정이 유효한가

3값 AND/OR 진리표 전수; 미입력 소득; 확정 FAIL+UNKNOWN; 빈 조건 리스트; LLM 결과 충돌 시험

## 되돌리거나 변경할 조건

공식 규칙 DSL과 운영 현실이 정교화되면 연산자 확장하되 비검증 조건을 PASS로 바꾸지 않음

## 구현·검증 상태

`[ ] 팀 승인` `[ ] 코드 대응 확인` `[ ] 실패 시험 통과` — 세 체크 모두 **검증 전**. ADR이 있다는 이유로 이 항목을 체크하지 않는다.
