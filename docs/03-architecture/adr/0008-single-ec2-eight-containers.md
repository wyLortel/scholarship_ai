# ADR-0008 — 1차 목표 배포는 단일 EC2 + 8개 컨테이너 + 관리형 RDS/S3

- 상태: `TARGET-DESIGN` · 최초 기록: 2026-11-18 (제공된 v7/업무 정의를 반영한 **팀 검토용 재구성**)
- 결정 주체: 프로젝트 팀(승인자/승인일 미입력). 이 문서는 라이선스/성능·실배포 검증 증거가 아님.
- 연결 요구사항/근거: `EV-09, EV-10, NFR-06`

## 맥락 — 문제가 무엇이고 왜 결정이 필요한가

교수님 대규모 수요 가정을 반영하되 팀 인력·기한이 제한적이다. 분리 가능한 실행 요소는 유지하되 당장 다중 서버 운영을 강요하면 위험이 커진다.

## 선택한 방향(팀 v7/업무 설계의 목표)

v7의 Phase 1은 EC2 한 대에 Nginx+React, FastAPI, Redis, Outbox Relay, Crawler, Agent Server x2, MCP를 컨테이너화하고 RDS/S3를 외부 관리형으로 쓴다.

## 검토해야 할 대안(비교 목록)

- 모놀리식 단일 프로세스
- 처음부터 MSA+Kubernetes/다중 AZ
- 모든 데이터를 EC2 로컬 볼륨에 저장

**선택 기준:** 도메인 정확성·학생 경험·작업 유실 위험·현재 팀 인력과 운영 부담·교수님의 대규모 가정. 대안이 정량 비교되었다는 주장은 하지 않는다.

## 얻는 것

단일 머신 배포·디버깅 단순화, 데이터 저장 계층은 EC2 장애와 분리, 역할별 컨테이너 확장 가능

## 감수할 대가 — 단점도 기록

EC2 호스트 단일 장애점, 컨테이너끼리 CPU/RAM 경합, 완전한 HA 없음

## 무엇을 검증해야 이 결정이 유효한가

8개 동시 구동 자원 측정, EC2 종료/재시작, 백업·복원, API/AI/알림 부하 간섭 테스트

## 되돌리거나 변경할 조건

측정된 병목이 나타나면 API·Crawler·Agent 분리, 필요 시 다중 AZ/ElastiCache 도입

## 구현·검증 상태

`[ ] 팀 승인` `[ ] 코드 대응 확인` `[ ] 실패 시험 통과` — 세 체크 모두 **검증 전**. ADR이 있다는 이유로 이 항목을 체크하지 않는다.
