# ADR-0007 — LangGraph Agent Server 도입은 라이선스·PoC 합격 후 조건부

- 상태: `CONDITIONAL` · 최초 기록: 2026-11-18 (제공된 v7/업무 정의를 반영한 **팀 검토용 재구성**)
- 결정 주체: 프로젝트 팀(승인자/승인일 미입력). 이 문서는 라이선스/성능·실배포 검증 증거가 아님.
- 연결 요구사항/근거: `EV-12, OPEN-11, FR-C02`

## 맥락 — 문제가 무엇이고 왜 결정이 필요한가

중단/재개·상태 관리·큐 운영을 자체 구현하면 학생 질문과 관리자 검토의 안정성 개발 부담이 크다. 그러나 도입 가능한 라이선스와 운영 기능은 확인되지 않았다.

## 선택한 방향(팀 v7/업무 설계의 목표)

v7 목표는 Agent Server 2개 실행 인스턴스 + Threads/Runs/Checkpoint/interrupt/resume. 먼저 자체 호스팅 라이선스/비용 공식 확인, 신청서 그래프 하나 PoC, Worker 강제 종료·interrupt 후 서버 재시작·중복 요청·스트리밍을 검증. 그 전에는 기존 자체 Worker 유지.

## 검토해야 할 대안(비교 목록)

- LangGraph 라이브러리+직접 worker/Redis 구현 유지
- Agent Server를 검증 없이 즉시 채택
- AI 장시간 작업 자체를 제외

**선택 기준:** 도메인 정확성·학생 경험·작업 유실 위험·현재 팀 인력과 운영 부담·교수님의 대규모 가정. 대안이 정량 비교되었다는 주장은 하지 않는다.

## 얻는 것

검증 통과 시 실행 관리 중복 구현 감소, 도메인 정확성에 개발 역량 집중

## 감수할 대가 — 단점도 기록

라이선스·운영비·버전·인프라 제약; API 호환/실패 복구 실제 동작 검증 필요; 벤더 종속성

## 무엇을 검증해야 이 결정이 유효한가

라이선스 문서·PoC 보고서, crash/resume/dup/stream 전수 확인. 통과 전 완료 표시 금지

## 되돌리거나 변경할 조건

라이선스/PoC 불합격·비용 초과 시 자체 Worker를 유지하고 ADR을 재작성

## 구현·검증 상태

`[ ] 팀 승인` `[ ] 코드 대응 확인` `[ ] 실패 시험 통과` — 세 체크 모두 **검증 전**. ADR이 있다는 이유로 이 항목을 체크하지 않는다.
