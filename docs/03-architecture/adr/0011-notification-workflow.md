# ADR-0011 — 검증된 신규·변경 공고의 가능 학생에게 알림함+FCM, 실행은 Agent Server 그래프

- 상태: `TARGET-DESIGN` · 최초 기록: 2026-11-18 (제공된 v7/업무 정의를 반영한 **팀 검토용 재구성**)
- 결정 주체: 프로젝트 팀(승인자/승인일 미입력). 이 문서는 라이선스/성능·실배포 검증 증거가 아님.
- 연결 요구사항/근거: `EV-08, BR-N01, BR-N02, BR-N03, OPEN-09`

## 맥락 — 문제가 무엇이고 왜 결정이 필요한가

학생들이 공고를 놓치는 문제를 덜고 싶다. 그러나 알림 폭주와 중복 발송이 신청 업무를 방해하거나 확인 필요 학생을 오안내할 수 있다.

## 선택한 방향(팀 v7/업무 설계의 목표)

검증된 공고 버전 이벤트+Rule Engine 가능 결과로 학생별 알림 기록 생성. v7 목표는 Agent Server 알림 그래프가 FCM 토큰 묶음을 발송하며 notify_jobs 전용 큐를 추가하지 않는다.

## 검토해야 할 대안(비교 목록)

- 모든 학생에게 무조건 알림
- Crawler가 곧바로 FCM 전송
- 별도 알림 큐/Worker를 초기부터 추가

**선택 기준:** 도메인 정확성·학생 경험·작업 유실 위험·현재 팀 인력과 운영 부담·교수님의 대규모 가정. 대안이 정량 비교되었다는 주장은 하지 않는다.

## 얻는 것

명시적 대상 기준, 학생 알림함 이력, 초기 작업 실행 구조 재사용

## 감수할 대가 — 단점도 기록

알림 작업이 신청 준비 run과 자원 경합, 중복 푸시 가능, 동의/토큰 운영 필요

## 무엇을 검증해야 이 결정이 유효한가

UNKNOWN 제외, 신규/변경만, 동일 학생·버전·종류 중복, FCM 실패/만료 토큰, 폭주 시 신청 지연 측정

## 되돌리거나 변경할 조건

신청 준비 지연·발송량 증가가 관측되면 별도 Notification Worker/큐 분리

## 구현·검증 상태

`[ ] 팀 승인` `[ ] 코드 대응 확인` `[ ] 실패 시험 통과` — 세 체크 모두 **검증 전**. ADR이 있다는 이유로 이 항목을 체크하지 않는다.
