# ADR-0004 — RDS PostgreSQL + pgvector에 업무·벡터 데이터를 통합

- 상태: `TARGET-DESIGN` · 최초 기록: 2026-11-18 (제공된 v7/업무 정의를 반영한 **팀 검토용 재구성**)
- 결정 주체: 프로젝트 팀(승인자/승인일 미입력). 이 문서는 라이선스/성능·실배포 검증 증거가 아님.
- 연결 요구사항/근거: `EV-10, BR-A07, NFR-06`

## 맥락 — 문제가 무엇이고 왜 결정이 필요한가

공고/학생/평가 등 관계형 데이터와 원문 검색 임베딩을 별도 저장소로 운영하면 동기화와 운영이 복잡하다. v7은 공고 규모 수천~수만 건을 가정했다(실제 측정은 아님).

## 선택한 방향(팀 v7/업무 설계의 목표)

업무 DB를 PostgreSQL로 통일하고 pgvector로 승인된 문장의 임베딩을 보관, 조건 SQL 필터와 의미 검색을 함께 수행. Agent Server checkpoint는 별도 database로 구분한다.

## 검토해야 할 대안(비교 목록)

- MySQL + Qdrant/별도 벡터 DB
- PostgreSQL + 외부 검색 엔진
- 문장 유사도 검색 제외

**선택 기준:** 도메인 정확성·학생 경험·작업 유실 위험·현재 팀 인력과 운영 부담·교수님의 대규모 가정. 대안이 정량 비교되었다는 주장은 하지 않는다.

## 얻는 것

동기화 부담·인프라 운영비·구성요소 수 감소; SQL 조건과 벡터 검색 결합 가능

## 감수할 대가 — 단점도 기록

벡터 쿼리와 OLTP가 DB 자원을 공유, 인덱스/쿼리 튜닝 필요, DB 부하 집중

## 무엇을 검증해야 이 결정이 유효한가

규모·동시성에 따른 검색 p95, DB pool·벡터 인덱스/복합 필터 측정; 승인 전 임베딩 비노출 테스트

## 되돌리거나 변경할 조건

벡터 쿼리가 주요 병목으로 측정되면 전용 벡터 저장소 분리를 재검토
