# ADR-0009 — 원문·작성 초안 파일을 S3에 두고 DB는 파일 참조/메타 관리

- 상태: `TARGET-DESIGN` · 최초 기록: 2026-11-18 (제공된 v7/업무 정의를 반영한 **팀 검토용 재구성**)
- 결정 주체: 프로젝트 팀(승인자/승인일 미입력). 이 문서는 라이선스/성능·실배포 검증 증거가 아님.
- 연결 요구사항/근거: `EV-06, EV-10, BR-C05, BR-C08`

## 맥락 — 문제가 무엇이고 왜 결정이 필요한가

공고 PDF/HWP/첨부와 작성 초안은 큰 바이트 데이터이며 버전·권한·다운로드 수명주기가 DB 행과 다르다.

## 선택한 방향(팀 v7/업무 설계의 목표)

S3 private object에 원문/초안 저장, DB는 파일 ID·해시·메타 참조. 임시 업로드→DB 기록→사용 가능 전환, 실패시 고아 파일 정리. 학생에게 단기 presigned URL.

## 검토해야 할 대안(비교 목록)

- 파일 바이트를 RDS BLOB에 직접 저장
- EC2 로컬 디스크 저장
- 공고 원문 저장하지 않음

**선택 기준:** 도메인 정확성·학생 경험·작업 유실 위험·현재 팀 인력과 운영 부담·교수님의 대규모 가정. 대안이 정량 비교되었다는 주장은 하지 않는다.

## 얻는 것

업무 DB 경량화·파일 이력/다운로드 관리·EC2 교체 시 보존

## 감수할 대가 — 단점도 기록

S3와 RDS 단일 트랜잭션 불가, 참조 정합성·권한·정리 작업 필요

## 무엇을 검증해야 이 결정이 유효한가

S3 성공+DB 실패, 동일 파일 중복 업로드, 타 학생의 초안 URL 접근, 만료 URL 실패 시험

## 되돌리거나 변경할 조건

문서 규모·보존 규정/비용으로 전략 변경 시 새 ADR과 마이그레이션 필요
