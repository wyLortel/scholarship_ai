# 횡단관심사 가이드

공고·판정·신청 준비에 반복해서 걸리는 문제는 적용 범위, 해결 방식, 확인 수단과 예외를 함께 정한다. 예를 들어 HTTP 요청과 수집 작업은 서로 다른 방식으로 실패를 알리지만, 실패 원인과 처리 결과를 추적할 수 있어야 한다.

> 팀 검토용 가이드. [v7 장애·보안 설계](../01-architecture-v7.md#11-장애재시도보안-품질-시나리오)와 ADR의 적용 리뷰에 사용한다. 표의 구현 수단은 적용 지점을 설명한다. 실제 구현·수치와 예외는 코드·테스트·[미결정 목록](../../00-governance/03-open-decisions.md)에서 확인한다.

## 우선 다룰 관심사

| 관심사 | 적용 범위와 처리 원칙 | 수단과 검증 |
|---|---|---|
| 오류 분류·전파 | API, Crawler, AI run에서 조건 결과·학생 답변 대기·원문 확인 실패·의존 시스템 장애를 구분한다. | API의 상태·오류 응답과 Crawler의 재처리 기록을 각 경계에 맞게 사용한다. 타임아웃을 주입해 성공 시각·변경 없음 처리와 분리되는지 확인한다. AC-A02, AC-C01. |
| 추적과 운영 지표 | 요청 접수, outbox 전달, 작업 실행, MCP 호출에서 `trace_id` 등 승인된 상관관계 식별자를 연결한다. | 운영 로그는 컴포넌트·오류 유형·처리 결과를 중심으로 남긴다. 정확한 소득·성적, 초안·프롬프트 본문, 토큰이 오류 로그·추적 데이터에 노출되는지 확인한다. NFR-05, OPEN-08. |
| 인증·권한·파일 접근 | 학생별 평가·준비 건·초안 및 내부 검토 행위에 서버 측 권한을 확인한다. | 리소스 소유권과 관리자 역할을 확인하고, MCP의 읽기 경계와 파일 링크 발급의 권한을 시험한다. 다른 학생의 계정으로 동일 식별자를 사용하는 AC-R05를 재현한다. [ADR-0009](../adr/0009-s3-file-boundary.md), [ADR-0010](../adr/0010-mcp-readonly.md), [ADR-0012](../adr/0012-no-personal-doc-uploads.md). |
| 트랜잭션·재시도·멱등성 | 준비 접수·작업 전달·결과 기록·외부 발송에서 각 단계의 중복과 귀속을 확인한다. 재시도는 일시적 장애에 한해 해당 작업의 계약에 따른다. | 업무 상태와 outbox의 원자적 기록, 단계별 중복 억제, 불확실한 외부 효과에 대한 재정합성을 검토한다. AC-R01, AC-R02, AC-R03, AC-R04, AC-R06. [ADR-0005](../adr/0005-async-outbox-idempotency.md), [ADR-0006](../adr/0006-separate-work-queues.md), OPEN-12. |
| 버전·시간·캐시 | 공고 조회, 평가, 준비 화면 이후에도 원문 버전과 마지막 성공 확인 시각이 연결되게 한다. 학생별 응답에 캐시를 적용할 때 사용자 범위와 최신성을 함께 본다. | 계약의 버전·시각 필드를 사용한다. 원문 확인 실패와 버전 갱신, 학생 계정 전환을 재현한다. AC-B07, AC-C01, AC-R05. [ADR-0003](../adr/0003-evidence-versioning.md). |

## 관심사가 부딪힐 때

- **관측성 × 개인정보** · 장애를 추적할 최소 필드로 시작한다. 업무 이력에서 필요한 원문·결정·버전을 조회할 수 있게 하고, 디버그 로그로 민감 본문이 복제되는지 확인한다.
- **복구 × 부작용** · Relay 전달 뒤 응답이 유실된 상황에서 준비 건 수, 결과 수, 외부 요청 수를 따로 관찰한다. 푸시 호출의 처리 여부가 불확실하면 알림 기록과 전송 상태를 구분한다. [ADR-0011](../adr/0011-notification-workflow.md)을 확인한다.
- **캐시 × 접근 권한·최신성** · 개인 응답을 공유하는 캐시 경로가 있는지, 권한 변경이나 검증된 새 버전 이후에도 이전 결과가 재사용되는지 확인한다.

## 적용 방법과 예외

첫 구현은 각 경계에서 기존 프레임워크·어댑터로 시작한다. 중복이 반복되는 공통 기술 처리에는 공통 코드나 프로젝트 템플릿을 검토한다. 검토 누락을 줄이려면 권한 테스트, 로그 필드 검사, 타임아웃·재전달 장애 주입 중 해당 위험에 맞는 수단을 선택한다.

HTTP와 비동기 작업의 처리 방식이 다를 때는 공통 원칙을 충족하는 방법을 PR에 적는다. 공통 설계에 예외가 필요하면 해당 구간, 이유, 보완 검증, 재검토 조건을 기록하고 기존 결정을 바꾸는 경우 [ADR 절차](../../04-delivery/workflow.md#3-무언가-바뀌었을-때--주인-문서를-먼저-고친다)를 따른다. 재시도 한도·시간초과·리소스 제한 수치는 OPEN-10과 OPEN-12에 연결한다.

### PR 체크리스트

- [ ] 영향받는 관심사, 적용 컴포넌트, 규칙을 지킬 수단과 예외를 적었다.
- [ ] 장애 주입 후 사용자·운영자가 보는 결과, 남은 기록 수, 로그 노출 범위를 확인했다.
- [ ] 관심사 사이의 충돌과 처리 근거를 설명하고, 미확정 수치는 OPEN에 연결했다.
