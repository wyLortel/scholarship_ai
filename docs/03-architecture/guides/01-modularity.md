# 모듈성 가이드

공고 기관의 응답 형식, 규칙 트리의 평가 방식, AI 제공사처럼 바뀔 수 있는 결정을 한곳에 숨긴다. PR에서는 변경이 필요한 모듈과 그 이유를 설명하고, 경계를 넘어가는 데이터는 소비자에게 필요한 계약으로 전달한다.

> 팀 검토용 가이드. 업무 규칙과 수용 기준은 [BR](../../01-domain/04-business-rules.md)과 [AC](../../04-delivery/01-acceptance-tests.md)를 따른다. 현재 `dev`의 `backend/app/`에는 업무 경계별 세 패키지(`notice/`, `eligibility/`, `preparation/`)가 있다([코드 지도](../../CODEMAP.md)). 아래 경계는 기능 구현 시 적용할 검토 기준이다.

## 어떤 결정을 어디에 숨기는가

| 바뀔 수 있는 결정 | 결정이 속하는 곳 | 경계에서 전달할 정보 |
|---|---|---|
| 기관별 HTML·API 필드와 첨부 파싱 방법 | 수집 어댑터. 공식성·버전·근거의 의미는 공고 모듈이 맡는다. | 기관 원문과 위치를 추적할 수 있는 수집 결과 |
| 규칙 트리 연산과 학생 사실 비교 | `backend/app/eligibility/domain/rules.py`의 Rule Engine | 버전이 고정된 규칙과 사실을 입력으로 받고, 조건별 결과와 근거가 담긴 평가를 제공한다. |
| 초안 생성 모델·SDK 응답과 저장소 구현 | 생성·저장 어댑터. 질문과 준비 건의 생명주기는 준비 모듈이 맡는다. | 확인된 사실 참조, 문항, 구조화된 초안 후보와 실패 정보 |
| 업무 데이터의 테이블·쿼리 | 데이터를 소유하는 쪽의 저장소 어댑터 | 식별자와 버전을 기준으로 한 조회·저장 계약 |

관련 규칙은 BR-A04, BR-A05, BR-B02, BR-B06, BR-C03, BR-C06과 [ADR-0001](../adr/0001-business-boundaries.md), [ADR-0002](../adr/0002-rule-engine-three-valued.md)를 확인한다.

## 경계 지키기

- **응집도**는 코드를 같이 바꾸는 이유로 본다. 규칙 비교와 조건별 이유 생성은 판정 근거에 함께 영향을 준다. 설명 문구나 프롬프트 수정은 같은 변경 이유에 속하지 않는다. `common`에 판정 규칙을 두면 여러 업무가 내부 정책에 의존하게 된다.
- **결합도**는 무엇을 알고 있는지로 본다. 도메인은 FastAPI, ORM, LLM SDK 구체 구현의 import 없이 테스트할 수 있게 한다. 다른 업무가 소유한 비공개 타입·DAO·테이블에 직접 의존하는지 확인한다.
- 모듈 사이 호출은 공개된 계약으로 연결하고, 역방향 호출이 필요해지면 유스케이스에서 두 모듈을 조정할 수 있는지 검토한다. 메시지를 쓰더라도 필드 구조, 이벤트 순서, 동기 응답에 대한 가정은 의존성으로 기록한다.
- 결합도를 수치로 살펴볼 때는 같은 단위에서 들어오는 의존 `Ca`와 나가는 의존 `Ce`를 센다. `Ce / (Ca + Ce)`는 어느 방향의 의존이 많은지 보는 참고값이다. 의존이 둘 다 없다면 계산을 생략한다.

## 변경 요청으로 검증하기

| 변경 요청 | 기대하는 변경 범위 | PR에서 볼 증거 |
|---|---|---|
| 기관 API의 게시일 필드 위치가 이동 | 해당 연동 어댑터와 fixture. 정규화한 값과 단위가 같으면 평가 코드 수정은 필요 없다. | 새 기관 응답 fixture로 공고 변환을 확인하고 기존 평가 입력으로 AC-B10을 재현한다. |
| 원문에 OR로 연결된 대안 자격이 추가 | 규칙 변환·검증과 기존 평가 계약이 해당 구조를 지원하는지 확인한다. UI는 구조화된 결과를 표시한다. | AC-B04, AC-B05, AC-B06과 대조해 평탄화, 검증 우회, 판정 중복을 확인한다. |
| 초안 생성 SDK 교체 | 후보 변환·실패 매핑이 바뀐다. 업무 전이나 사실 검증이 함께 바뀐다면 그 이유를 적는다. | 기존 입력/출력 fixture 및 AC-C03, AC-C06으로 재개와 초안 사실성을 확인한다. |

### PR 체크리스트

- [ ] 변경 이유와 이를 숨길 모듈을 한 문장으로 적었다. 변경이 퍼진 각 위치에 이유가 있다.
- [ ] Python 및 TypeScript import를 검토해 내부 또는 역방향 참조를 찾고, 저장소 조회와 작업 순서도 확인했다.
- [ ] 경계 밖의 기존 동작을 관련 AC로 확인했다. 반복되는 정적 위반에는 의존 검사 도입을 검토한다.
