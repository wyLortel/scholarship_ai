# 컴포넌트 분할 가이드

요구사항에서 누가 어떤 업무를 끝까지 책임지는지 정하고, 그 업무의 변경을 한 경계에 모은다. FastAPI, PostgreSQL, AI 실행 환경은 각 업무를 지원하는 기술 역할이다. 팀의 기준 경계는 [ADR-0001](../adr/0001-business-boundaries.md), 런타임 배치는 [v7 아키텍처](../01-architecture-v7.md)에서 확인한다.

> 팀 검토용 가이드. `dev`의 백엔드는 업무 경계별 폴더(`notice/`, `eligibility/`, `preparation/`)이고, 계층은 폴더 안의 파일 이름(`router.py`, `service.py`, `model.py`·`rules.py`, `repository.py`)으로 나눈다([코드 지도](../../CODEMAP.md)). 표는 요구사항 배치에 쓰는 논리 지도이며, 추가 패키지와 배포 단위는 필요가 확인될 때 검토한다.

## 요구사항과 책임 배치

| 업무 컴포넌트 | 책임과 관리하는 기록 | 요구사항과 확인 사례 |
|---|---|---|
| 공고·근거 관리 A | 공식 출처에서 얻은 공고의 원문 버전, 근거, 규칙 검증 이력을 관리한다. | FR-A02, FR-A03 · AC-A02, AC-A03 |
| 자격 판정 B | 버전이 고정된 규칙과 학생 사실로 평가를 만들고 조건별 결과를 관리한다. | FR-B02, FR-B04 · AC-B04, AC-B07, AC-B10 |
| 신청 준비 C | 준비 건에서 최신성 확인, 질문, 체크리스트, 초안 이력을 이어 간다. | FR-C01, FR-C02, FR-C03, FR-C04 · AC-C01, AC-C03, AC-C06 |
| 내부 검토 | 추출 내용과 원문의 정합성에 대한 검토 결정을 기록한다. 공고의 검증 상태는 공고 모듈과 협력해 처리한다. | FR-A04 · AC-D04, AC-D05 |
| 알림 | 공고 변경과 평가 결과를 받아 학생별 알림 기록과 발송 요청을 관리한다. | FR-N01 · AC-N01, [ADR-0011](../adr/0011-notification-workflow.md) |

## 새 기능을 어디에 둘지 결정하기

1. 학생 또는 운영자가 하려는 일을 동사로 적고 [PRD](../../02-product/01-PRD.md)에서 FR을 찾는다. 예를 들어 ‘학생 답변을 받고 준비 건을 재개한다’는 준비 건과 질문의 상태가 함께 바뀌는 FR-C02 유스케이스다.
2. 업무 결과를 책임질 컴포넌트 하나를 정한다. 관련 규칙·상태·테스트를 그 책임에 연결하고, 다른 컴포넌트에 필요한 요청·응답과 데이터 쓰기 소유자를 적는다. 위 예의 준비 상태는 C가 관리한다. 재평가가 필요한 경우 새 자격 결과는 B가 관리한다.
3. 기능 폴더 안에서 계층별 파일에 작업을 배치한다. `router.py`는 HTTP 입력·응답을 변환하고, `service.py`는 권한이 확인된 흐름과 트랜잭션을 조정한다. `model.py`·`rules.py`는 업무 결정을, `repository.py`와 그 구현(`fixture_*.py` 등)은 저장·외부 연동을 맡는다. 실제 호출 방향과 소유권은 [도메인 모델](../../01-domain/07-domain-model.md)로 확인한다.
4. 분리 후보는 변경 이유, 데이터 소유권, 보안·성능 영향, 협의 비용으로 다시 본다. 팀의 기능 담당자가 변경을 끝까지 설명하고, 연동되는 계약이 바뀔 때 소비자와 함께 검토한다.

## 이 정도로 나누는 이유

- **추출과 근거 검증**은 A 안에서 검증 전후의 모델·상태를 구분한다. 같은 공고 버전의 생명주기를 다루므로 각 단계마다 새 서비스나 테이블 전용 컴포넌트를 만들 필요가 있는지 별도로 검토한다. AC-A03을 경계 확인에 쓴다.
- **질문과 초안**은 C의 같은 준비 건과 진행 기록을 사용한다. `QuestionManager`와 `DraftManager`가 서로의 상태를 수정하기 시작하면 전이를 어디에서 통제할지 다시 정한다. AC-C03, AC-C06을 함께 본다.
- **수집과 알림**은 공고 변경에 함께 반응하지만, 공고 원문 수집과 학생별 발송 이력의 변경 이유가 다르다. 논리 책임은 구분하되 큐·프로세스 분리는 [ADR-0006](../adr/0006-separate-work-queues.md), [ADR-0007](../adr/0007-agent-server-gate.md), ADR-0011과 운영 증거를 함께 검토한다.

### PR 체크리스트

- [ ] FR마다 주 책임, 입력·출력, 데이터 쓰기 소유자, 관련 AC를 지정했다.
- [ ] 하나의 기능을 고칠 때 늘 함께 움직이는 경계가 있다면 이유를 확인했다. 같은 책임을 잘게 쪼갠 결과인지 검토했다.
- [ ] 소비하는 컴포넌트가 공개 계약으로 협력하고, 팀원이 변경 영향과 필요한 리뷰를 설명할 수 있다.
