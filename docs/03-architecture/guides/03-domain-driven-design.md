# 도메인 주도 설계 가이드

학생과 팀이 쓰는 말에서 출발해, 같은 용어와 규칙이 일관되게 통하는 범위를 정한다. A/B/C는 업무를 살펴보는 출발점이다. 모델 경계는 누가 결정을 내리고, 어떤 시점의 사실을 보존하며, 다음 업무에 무엇을 전달하는지로 검증한다.

> 팀 검토용 전략 설계 가이드. 명칭은 [용어집](../../01-domain/03-glossary.md), 객체와 소유권은 [도메인 모델](../../01-domain/07-domain-model.md), 상태는 [상태 전이](../../01-domain/06-state-machines.md)를 따른다. 컨텍스트는 모델의 사용 범위를 나타내며, 프로세스 배치는 [ADR-0001](../adr/0001-business-boundaries.md)과 v7에서 별도로 검토한다.

## 같은 말이 쓰이는 곳을 확인한다

| 모호한 말 | 문서·코드·테스트에서 구분할 모델 | 찾아볼 원본 |
|---|---|---|
| 공고 | A의 `Notice`는 모집 회차, `NoticeVersion`은 당시 공식 원문을 가리킨다. B는 평가에 사용한 버전을 붙이고, C는 준비 건에서 확인할 버전을 다룬다. | [공고 거버넌스](../../01-domain/08-notice-governance.md), BR-A04, BR-A08, AC-B07 |
| 조건 | A의 `ConditionCandidate`는 추출 후보, `VerifiedRuleSet`은 인계 가능한 검증 규칙이다. B에서 학생별 조건 결과를 생성한다. | BR-A05, BR-B02, AC-A03, AC-B05 |
| 학생 정보 | 변경 가능한 `StudentProfile`과 특정 평가에 사용한 `StudentFactSnapshot`을 이름과 시점으로 구분한다. | [자격 판정 정책](../../01-domain/05-eligibility-policy.md), BR-B01, AC-B10 |
| 완료 | `executionStatus`의 실행 완료, C의 `preparationStatus`, 기관의 접수 여부는 각각 다른 질문에 답한다. | [신청 준비 규칙](../../01-domain/09-application-preparation.md), BR-C07, AC-C07 |
| 승인 | 내부 검토의 승인 대상과 기관의 선발 판단을 화면·로그·테스트 이름에서 구분한다. | BR-O01, BR-O03, AC-D04 |

## 컨텍스트 사이에서 건네는 것

| 제공 → 수신 | 전달할 업무 정보 | 관계와 검토 포인트 |
|---|---|---|
| 외부 기관 → A | 공식 원문·첨부와 기관의 모집·공고 식별 정보 | 기관별 형식은 수집 경계에서 변환하고 원문을 추적할 수 있게 한다. 부패 방지 계층(ACL)을 적용할 수 있는 지점이다. |
| A → B | 공고 버전 참조, `VerifiedRuleSet`, 근거 위치 | B가 재현 가능한 평가에 필요한 정보를 계약으로 받는다. A가 공고 버전과 근거의 주인이다. |
| A와 B → C | A의 버전·최신성·서류/문항 정보, B의 `EligibilityAssessment` | C는 준비 건의 상태를 책임지고 결과와 버전을 참조한다. 버전이 달라졌을 때는 AC-C01, AC-C02와 OPEN-04를 확인한다. |
| 내부 검토 → A | 검토 대상의 버전, 결정 및 사유 | 검토는 결정을 남기고 A는 해당 결정에 따른 검증 상태 변경을 맡는다. AC-D04, AC-D05를 확인한다. |
| A와 B → 알림 | 검증된 공고의 신규·변경 정보와 해당 버전의 평가 | 알림은 발송에 필요한 범위만 소비한다. AC-N01과 [ADR-0011](../adr/0011-notification-workflow.md)을 확인한다. |

A가 제공하는 정보의 의미나 구조를 바꾸면 B·C의 요구와 전환 일정을 함께 확인한다. 공유 타입이 필요하면 값의 의미가 실제로 같고 변경을 함께 검토할 수 있는 작은 범위부터 검토한다.

## 변경 사례로 경계를 검증한다

가상 공고 V1의 평가를 저장한 뒤 기관이 V2를 발표했다고 가정한다. 공고 버전 이력, V1 평가 당시의 학생 사실, 준비 건의 현재 진행은 바뀌는 이유와 소유자가 각각 다르다. 설계 리뷰에서는 V1 평가를 어떻게 재현하는지, 누가 V2 검증 결과를 인계하는지, 준비 화면이 V1 평가를 어떤 상태로 표시하는지 그림이나 흐름으로 설명한다. 근거는 AC-B07, AC-C01, AC-C02, OPEN-04에 연결한다.
