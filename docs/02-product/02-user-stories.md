# 학생/운영자 스토리맵과 우선순위

> 책임: 학생이 목표를 달성하는 **행동 순서와 검증 가능한 가치**. 내부 서버 구조를 이야기하지 않는다. `R1/R2/R3`는 구현 완료가 아닌 추천된 학습·시연 순서다.

## 학생의 활동 순서

| 결과(가로) | 1. 찾기 | 2. 조건 정리 | 3. 자격 이해 | 4. 보완 | 5. 자료 준비 | 6. 본인 검토·제출 |
|---|---|---|---|---|---|---|
| 사용자의 욕구 | 공식 후보 찾기 | 실제 아는 사실 제공 | 이유 있는 판정 얻기 | 모름 해결 | 서류·글 초안 확보 | 안전하게 직접 제출 |
| R1 핵심 | ST-01 후보·근거 보기 | ST-02 모름 입력 | ST-03 3값 결과·근거 | ST-04 미확인 항목 표시 | ST-05 기초 체크리스트 | ST-06 공식 경로·경계 |
| R2 확장 | ST-07 자동 출처/버전 확인 | ST-08 저장/수정 | ST-09 공고 변경 반영 | ST-10 질문·중단·재개 | ST-11 초안 생성·검증 | ST-12 확인·다운로드 |
| R3 자동화 | ST-13 관련 새 공고 알림 | — | ST-14 알림에서 재판정 | — | ST-15 기관·문서 유형 확대 | — |

## 운영자의 활동 순서

| 결과 | 1. 원문 확인 | 2. 추출 검토 | 3. 결정 | 4. 영향 재평가 |
|---|---|---|---|---|
| 운영 스토리 | OP-01 원문·버전 비교 | OP-02 불일치 확인 | OP-03 승인·수정·반려 | OP-04 중단 작업 재개·결과 확인 |

## 핵심 유저 스토리/수용 기준 (각 항목이 사용자 가치를 가져야 함)

| ID | 유저 스토리 | acceptance (간략) | 근거 |
|---|---|---|---|
| ST-01 | 학생으로서 검색어를 몰라도 공식 공고를 찾아보고 싶다 | 공고·기관·공식 원문 링크·확인 시각 보기 | P-01/02, A-01 |
| ST-02 | 학생으로서 정확히 모르는 소득구간을 모름으로 입력하고 싶다 | 빈 값은 FAIL/0이 아닌 UNKNOWN | D2 / BR-B01 |
| ST-03 | 학생으로서 왜 지원 가능/불가/확인 필요인지 알고 싶다 | 각 조건·버전·근거·사유 표기 | D1 / BR-B03~B07 |
| ST-04 | 학생으로서 기관에 확인할 내용을 구분하고 싶다 | `정보 미입력`과 `기관 해석 필요` 구분 | D2 / BR-C04 |
| ST-05 | 학생으로서 필요한 서류/발급처를 미리 알고 싶다 | 공고별 체크리스트, 출처 확인 | D1 / BR-C05 |
| ST-06 | 학생으로서 실제 제출해야 하는 곳을 알고 싶다 | 공식 URL 안내, 제출 여부 자동 확정 금지 | D1 / BR-C07 |
| ST-07 | 학생으로서 과거 공고와 최신 공고를 구분하고 싶다 | 새 버전/성공·실패 확인 시각 표시 | D3 / BR-A04/A09 |
| ST-08 | 학생으로서 나중에 정보를 고쳐도 앞선 입력을 잃고 싶지 않다 | 본인 스냅샷/결과 이력 분리 | D2 / BR-C03 |
| ST-09 | 학생으로서 조건이 바뀌면 다시 판단받고 싶다 | 이전 평가 stale 표시, 새 버전 평가 | D3 / BR-A08 |
| ST-10 | 학생으로서 질문에 답할 때 이어서 작성하고 싶다 | 새로고침·재로그인·재개; 중복 없이 | D2 / BR-C03 |
| ST-11 | 학생으로서 작성 부담을 줄이고 싶다 | 사실 기반 초안/문항 적합성 검사 | D1 / BR-C06 |
| ST-12 | 학생으로서 초안을 고치고 직접 제출하고 싶다 | 검토·다운로드·공식 링크; 준비완료 ≠ 접수 | D1 / BR-C07 |
| ST-13 | 학생으로서 관련 새 공고를 놓치고 싶지 않다 | 검증된 신규/변경 + 가능만 알림 기록 | N-01 / BR-N01 |
| OP-01 | 검토자로서 원문을 확인하고 싶다 | 원문 파일/버전/문장 위치 노출 | D4 / BR-O01 |
| OP-02 | 검토자로서 추출이 왜 모호한지 알고 싶다 | 문제 조건·추출 후보·사유 표시 | D4 / BR-A06 |
| OP-03 | 검토자로서 잘못 읽은 조건을 수정하고 싶다 | 승인/수정/반려+근거/감사 | D4 / BR-O01/O02 |
| OP-04 | 검토자로서 수정 영향이 반영됐는지 알고 싶다 | 해당 버전 재검증과 이어하기 상태 | D4 / BR-O02 |

## 대표적인 사용자 시연 흐름

1. R1(핵심 업무 검증): **가상 검증 공고 2건**에서 학년/소득 `모름` 입력 → 3값 결과와 원문 근거 → 체크리스트(가능하면 최소 한 개).
2. R2(업무 유지·확장): 학생 대기/재개, 변경된 공고 재판정, 내부 검토, 사실 기반 초안 다운로드.
3. R3(운영 자동화): 기관 수집 API·Playwright 확장, 알림함/FCM, 트래픽·복구 검증.

일정·실제 누가 언제 구현하는지는 팀 결정. **원래 목표 업무 A/B/C 전체를 유지하면서** 한 번에 끝까지 작동하는 작은 슬라이스부터 검증하려는 제안이다.
