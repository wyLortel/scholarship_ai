# 신청 준비 업무 계약 — 질문·체크리스트·초안·인간 확인

> 책임: **C 업무에서 입력이 어떻게 준비 자료가 되는가**. AI 그래프 라이브러리 API 문서가 아니다. 기술적 저장/재개 책임은 architecture/ADR로 이어진다.

## 준비 업무의 진입 조건

- `student_id`, `notice_id`, 현재로 확인할 수 있는 `notice_version_id`, 해당 학생의 최신 **평가 스냅샷** 필요.
- 준비 직전 최신 원문 확인 결과를 받는다(`BR-C01`). 확인 실패/변경/불가이면 해당 사실을 그대로 표시하고 넘어갈지/중단할지 정책 적용.
- 명백한 새 버전 FAIL 시 중단(`BR-C02`). UNKNOWN은 자동 FAIL이 아니므로 확인 사항을 붙이고 진행 가능한 범위를 분리.
- **준비 건 하나 = 특정 학생이 특정 공고에 신청을 준비하는 작업**. 중복 클릭으로 별개의 작업이 무한 생성되지 않게 요청 ID 정책 필요.

## 1. 학생에게 질문할 때 필요한 정보

| 요소 | 구체적인 의도 | 예시(가상) |
|---|---|---|
| `question_id` | 응답과 대기 상태를 안정적으로 연결 | `q-income-1` |
| `reason_code` | 왜 지금 묻는지 표시 | `MISSING_FACT` |
| `related_rule_id` | 어느 조건을 판단하려는 질문인지 연결 | `income_bracket_rule` |
| `expected_fact` | 값·단위·기준 시점 | `income_bracket / integer / source_year` |
| `question_text` | 비개발자도 답할 수 있는 말 | ‘공고가 요구하는 기준 연도의 소득구간을 알고 있나요?’ |
| `answer_status` | answered / unknown / needs_institution | `unknown` |
| `resume_token_ref` | 같은 건의 이어가기 연결(서버측 권한 검증) | `opaque-id` |

학생이 `'모름'`이라고 답하면 같은 질문을 무한반복하지 않는다. **확인 경로를 안내하고 대기 또는 기관 확인 필요로 전환**한다. 개인정보를 외부 LLM으로 보낼 때 최소화·마스킹 정책 필요.

## 2. 서류 체크리스트 생성

- **입력:** 검증된 공고 버전의 서류 요구/해당 조건 + 원문 증거 anchor.
- **출력 항목:** 서류명, 왜 필요한지(원문 문장), 적용 대상/조건, 발급 주체, 공식 안내 URL(검증된 경우), 필요한 시점, 학생 확인 상태, 근거/버전.
- **금지:** 존재하지 않는 발급 서비스 URL 창작; 모든 학생에게 조건부 서류를 무조건 요구; 학생에게 이 서비스로 실제 증빙 업로드 요청.
- **확인 필요 항목:** 공식 안내가 없다면 `발급처 확인 필요`로 표시한다.

## 3. 초안 생성과 검증

**허용 입력:** 학생이 제공·검토한 활동 사실, 공고에 공개된 신청서 질문/글자 제한/형식, 필요 시 사용자가 승인한 메모. **증빙 파일을 받지 않는다**.

1. 각 질문에 대응하는 `DraftSection`을 만든다.
2. 서술할 모든 사실 문장에 `student_fact_ref` 또는 학생이 이번 턴에서 확인한 서술을 연결한다.
3. 정보가 없으면 `[확인 필요: 해당 경험]` 같은 플레이스홀더나 질문으로 남긴다.
4. 지원 공고의 문항·제한 글자수(확인 가능할 때)를 점검한다.
5. 금지 내용: GPA/연봉/소득/수상/봉사·수혜 이력/출석 등 **제공되지 않은 사실 생성**.
6. 학생에게 **초안**임을 표시하고 검토하도록 안내한다. 최종 제출은 학생 책임.

### 작성 예

- 공고 문항(가상): `지원 동기 500자 이내`.
- 학생이 제공한 사실: `교내 멘토링 2회 참여`.
- **가능:** ‘교내 멘토링에 두 차례 참여하며 ...’ (단, 결론·감정·성과는 학생이 확인해야 함).
- **금지:** ‘수년간 멘토링을 이끌어 장학생으로 선정되었다’ (제공되지 않은 성과/수혜 이력).

## 4. 세 가지 결과를 분리

| 결과 | 언제 | 사용자가 볼 문구 원칙 |
|---|---|---|
| `PREPARED` | 준비 자료/확인 항목이 정리됨 | 자료 준비 완료. **공식 제출은 직접** |
| `PREPARED_WITH_OPEN_ITEMS` | 문서 준비는 됐지만 UNKNOWN/기관 확인 사항 남음 | 자료 준비 완료·확인 필요 항목 남음. 지원 가능 확정 아님 |
| `STOPPED` | 변경 공고로 확정 불가, 검토 반려 등 | 중단 이유·새 기준·다음 행동 표시 |

`SUBMITTED`는 외부 기관의 접수 사실이며 본 서비스가 알 수 없는 한 자동 상태로 만들지 않는다.

## 5. 사람이 반드시 통제하는 단계

- 공고 담당자: 실제 기관 규칙의 의미.
- 내부 검토자: 원문 대비 추출 정합성.
- 학생: 자기 정보 확인, 초안 사실 검토·다운로드·기관 직접 제출.
- 서비스: 비교·근거 제시·체크리스트·안내·대기/재개.

## 6. 실패·중단/재개 테스트 예

- 질문 대기 중 브라우저 새로고침/서버 재시작 → 같은 준비 건, 선택 공고, 질문/기존 답변을 복원.
- 재개 API를 같은 키로 두 번 호출 → 학생 답변과 결과가 두 번 적용되지 않음.
- 외부 LLM 문장 작성 실패 → 원래 계산된 자격 판정을 변경하지 않고 초안 실패만 표시.
- 공고 변경 중 문안 생성 → 이전 버전 기반 초안을 새 버전 최신으로 표시하지 않음.
- UNKNOWN 포함 상태로 준비 마침 → 화면에 미확인 조건과 공식 문의처를 계속 표시.
