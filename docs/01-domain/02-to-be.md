## 0. 현재 업무 (AS-IS)

> 서비스를 만들기 전 학생과 기관이 하는 업무만 설명한다. 인터뷰 원문으로 검증된 한 사람의 경로가 아니라 팀 조사 메모를 연결한 **재구성**이다. UI/DB/프레임워크는 등장하지 않는다.

### AS-00 — 학생이 장학금을 발견하고 직접 준비한다

- **행위자:** 장학금 공고 기관 담당자, 학생, 친구·지인, 증빙 발급기관, 장학금 신청기관.
- **업무 대상:** 모집 공고, 지원 조건, 학생의 학적/소득 등 사실, 필요 서류, 신청서, 제출 내역.
- **시작:** 기관이 장학금 모집 공고를 게시함.
- **정상 사례 전제:** 학생이 공고를 발견하고 자격을 해석할 수 있으며 필요 서류를 발급받을 수 있음. 실제 학생 전원이 같은 순서로 행동한다는 주장은 아님.

| # | 누가 | 무엇을 한다 | 다루는 정보·물건 | 누구에게/결과 |
|---|---|---|---|---|
| 1 | 기관 | 게시한다 | 공식 모집 공고 | 공식 사이트 |
| 2 | 친구·지인/검색 서비스 | 알려준다 | 장학금 소식 | 학생 |
| 3 | 학생 | 찾고 원문을 읽는다 | 모집 공고·최신 공지 | 학생의 후보 목록 |
| 4 | 학생 | 자기 조건과 대조한다 | 학적·지역·소득구간 등 | 지원 대상인지 판단 |
| 5 | 학생 | 다시 확인한다 | 예외/소득 산정 연도/공고 변경 | 기관 사이트, 필요하면 문의 |
| 6 | 학생 | 정리한다 | 서류 목록·마감·작성 항목 | 개인 준비 목록 |
| 7 | 학생 | 발급받는다 | 각종 증빙 서류 | 발급기관 |
| 8 | 학생 | 작성·검토한다 | 신청서·자기소개서·학업계획서 | 제출할 서류 |
| 9 | 학생 | 직접 제출한다 | 준비한 신청 자료 | 해당 장학금 기관 |

### 관찰된/조사에서 정리된 마찰 (인터뷰·온라인 자료 혼합 요약)

| 문제 ID | 기존 요약에서 제기된 불편 | 어느 행동에서 드러나는가 | 왜 중요한가 | 아직 모르는 것 |
|---|---|---|---|---|
| P-01 | 제도명·검색어·발견 경로를 모름 | 2~3 | 지원 자격이 있어도 공고를 찾지 못할 수 있음 | 얼마나 자주 발생하는가 |
| P-02 | 광고/블로그/다른 지역 정책이 섞임 | 3 | 공식 원문과 관련 범위를 찾기 어려움 | 대표 실제 검색 기록 |
| P-03 | 예전 공고와 최신 공고가 혼재 | 3,5 | 바뀐 기준으로 잘못 판단 가능 | 변경 빈도/기관별 게시 방식 |
| P-04 | 소득 기준연도·학적/휴학/근로의 의미가 모호 | 4,5 | 스스로 PASS/FAIL을 오판 가능 | 기관의 공식 예외/해석 |
| P-05 | 마감 외 예산 소진/사전 절차를 뒤늦게 발견 | 5~6 | 서류 준비한 뒤 신청 자체가 어려울 수 있음 | 해당 공고가 실제로 어떤 조건을 규정했는가 |
| P-06 | 필요한 서류와 작성 부담 | 6~8 | 준비 오류와 반복 확인 | 가장 부담되는 서류의 종류 |

### 우리가 아직 관찰했다고 주장할 수 없는 것

- 특정 학생의 실제 시간·횟수·신청 포기율·절약 시간·합격율.
- 인터뷰 응답자의 정확한 원문 발언이나 대표성이 있는 통계.
- 모든 기관의 서류 발급 순서·신청 자격 규칙이 동일하다는 일반화.

### 핵심 업무 문제의 정의

> 학생이 공식 공고를 발견하고 자신의 조건을 해석하며 준비하는 과정에서, **근거·최신성·미확인 항목을 명확히 구분하기 어려워 잘못된 결정을 할 수 있다.**

## 행위자와 업무 대상

- 행위자: 학생, 장학금 기관(공고 게시/외부 제출·심사), 우리 서비스, 내부 검토자, 필요 시 증빙 발급기관.
- 업무 대상: 공식 출처, 공고 원문, 공고 버전, 검증된 조건과 근거, 학생 조건, 조건별 판정, 질문/답변, 준비 건, 서류 목록, 작성 초안, 알림, 내부 검토 결정.
- **정상 흐름 먼저 / 예외는 따로:** A/B/C 및 D1을 기본으로 읽고 D2(정보 부족), D3(공고 변경), D4(검토)에서 복잡도를 추가한다. 이 그림은 미래 업무 **팀 설계안**이지 인터뷰로 관찰된 현재 업무가 아니다.

## A-01 공식 공고 수집·검증

**시작:** 등록된 공공데이터/기관 출처를 확인할 시점 도래.

| # | 행위자 | 행동 | 객체 | 판단/다음 결과 |
|---|---|---|---|---|
| A1 | 서비스 | 찾아본다 | 등록된 기관 사이트/공공데이터의 공고 후보 | 후보의 출처 확인 |
| A2 | 서비스 | 구분한다 | 신규 / 변경 / 변경 없음 | 변경 없음이면 해당 회차 종료 |
| A3 | 서비스 | 보관한다 | 신규·변경 원문과 첨부, 버전, 확인 시점 | 과거 버전 유지 |
| A4 | 서비스(AI 보조) | 후보를 추출한다 | 자격 조건·서류·기한과 원문 위치 | **아직 검증되지 않은 추출** |
| A5 | 서비스 | 대조한다 | 후보 조건 ↔ 공식 원문의 문장 | 불일치/모호성 판단 |
| A6 | 서비스 | 보완한다 | 검증 실패 추출 | 정해진 범위 안에서 재추출 |
| A7 | 서비스 | 넘긴다 | 계속 불일치 또는 해석 불가 조건 | 관리자 검토로 대기 |
| A8 | 서비스 | 승인된 근거를 등록한다 | 검증된 공고 버전·조건·근거 | 색인·판정 대상 |

**특별 경계:** 웹/뉴스에서 **새 기관을 발견**하면 후보 목록에 둘 수 있으나, 공식 확인 전에는 승인된 장학금 출처가 아니다. 의미 검색은 공식 원문 문장을 찾는 보조 수단이지 최종 판정 근거가 아니다.

## B-01 학생의 자격 판정·추천

**시작:** 학생이 학생 조건을 제공하거나 검증된 공고가 신규·변경 등록됨.

| # | 행위자 | 행동 | 객체 | 판단/다음 결과 |
|---|---|---|---|---|
| B1 | 학생 | 제공한다 | 지역, 학적, 소득구간 등 실제 아는 사실 | 모르는 값은 모름으로 남김 |
| B2 | 서비스 | 찾는다 | 학생 정보와 관련 있는 **검증된** 공고 | 후보 제시 |
| B3 | 서비스 | 비교한다 | 구조화된 공고 조건과 학생 값 | 개별 PASS / FAIL / UNKNOWN |
| B4 | 서비스 | 조합한다 | 조건별 결과 | 가능 / 불가 / 확인 필요 |
| B5 | 서비스 | 설명한다 | 결과, 조건별 근거, 버전, 확인 시점 | AI 설명이 Rule Engine 결과를 변경 못 함 |
| B6 | 학생 | 확인한다 | 가능 / 확인 필요 / 불가 그룹 및 상세 근거 | 준비 여부 결정 |

**중요:** `가능`은 공고 자격 **조건 판정**이지 실제 선발·지급 보장이 아니다. 공고의 필수 조건 중 확정된 미충족이 있으면 불가, 미충족 없이 모름이 있으면 확인 필요. 단, OR/예외 조건은 실제 공고의 논리 구조에 따라 평가한다.

## C-01 신청 준비

**시작:** 학생이 선택한 공고로 `신청 준비하기`를 요청함.

| # | 행위자 | 행동 | 객체 | 판단/다음 결과 |
|---|---|---|---|---|
| C1 | 서비스 | 최신 상태를 확인한다 | 해당 공식 공고·버전 | 변경 시 재추출·재판정, 실패 시 미확인 표시 |
| C2 | 서비스 | 준비해도 되는지 다시 확인한다 | 최신 자격 결과 | 변경 후 확정 FAIL이면 준비 중단 이유 안내 |
| C3 | 서비스 | 정리한다 | 최신 공고의 필요 서류·발급 경로·작성 문항 | 체크리스트 |
| C4 | 서비스 | 질문한다 | 부족한 사실/질문 이유 | 학생 답변까지 대기·상태 보존 |
| C5 | 학생 | 대답하거나 확인 필요로 남긴다 | 자기 조건/경력/활동 등 | 같은 준비 건에서 재개 |
| C6 | 서비스(AI 보조) | 초안을 작성한다 | 확인된 사실, 원문 문항, 형식 | 자기소개서·학업계획서·신청서 초안 |
| C7 | 서비스 | 검증한다 | 초안에 포함된 주장과 근거·문항 적합성 | 확인 불가 내용은 보완 또는 표시 |
| C8 | 학생 | 확인하고 내려받는다 | 체크리스트·초안 | 서비스 내부 준비 마침 |
| C9 | 학생 | 직접 발급·제출한다 | 증빙서류·기관 신청 서류 | 외부 기관 업무; 우리 서비스는 결과 미확인 |

**중요:** 질문을 다 못 풀어도 `UNKNOWN/기관 확인 필요`를 **명시**하고 준비를 마치는 흐름이 원본에 있다. 이를 `지원 가능 확정`이나 `공식 신청 완료`로 바꾸면 안 된다. v6/v7은 개인 증빙서류 업로드/저장/검증이 아닌 **발급·준비 방법 안내**다.

## D1 — 정상 준비: 가능 판정에서 준비까지

**가정:** 검증된 시험 공고의 적용 필수조건을 모두 충족하고 충분한 작성 사실이 있음.

1. 학생이 조건을 입력한다.
2. 서비스가 가능 공고를 보여주고 버전별 근거를 안내한다.
3. 학생이 선택한 공고의 최신 상태를 재확인한다.
4. 서비스가 서류 체크리스트·발급 경로·사실 기반 작성 초안을 제공한다.
5. 학생이 확인하고 내려받는다. 서비스 업무의 끝은 `준비 완료`다.
6. 학생이 외부 공식 신청 사이트에 직접 제출한다(서비스는 접수 사실을 자동 확정하지 않음).

## D2 — 정보 부족: 모름 → 질문 → 보존 → 재개

**가정:** 학생이 공고에서 필요한 소득구간을 모름.

1. 서비스가 해당 조건을 UNKNOWN, 전체 결과를 확인 필요로 표시한다.
2. 어떤 기준 연도/값이 필요한지와 이유를 물어본다.
3. 학생이 지금 모른다고 하면 `질문 대기`로 남기며 앞선 응답을 저장한다.
4. 학생이 나중에 답하면 **같은 준비 건**에서 이어가고 다시 평가한다.
5. 스스로 결정할 수 없는 것은 `기관 확인 필요`를 표시한다. 기관 답변을 만들어내지 않는다.

## D3 — 공고 변경: 이전 근거를 새 근거로 재확인

1. 기관이 기존 공고를 변경한다.
2. 서비스가 변경을 감지하고 기존 버전을 보존한 채 새로운 버전 원문을 기록한다.
3. 새 원문의 조건을 다시 추출하고 근거와 대조한다.
4. 검증되면 해당 버전에 의존한 이전 판정·준비 건을 재평가 대상으로 분리한다.
5. 학생에게 예전/현재 버전·확인 시점과 달라진 결과를 설명한다.
6. 새 조건상 확정 FAIL이면 해당 신청 준비를 중단하고 이유를 안내한다.

**예외:** 새 공고 접근 실패/원문 검증 실패는 `변경 없음`이나 `최신 확인 완료`가 아니다.

## D4 — 모호한 추출: 검토 후 재개 또는 반려

**시험 예시:** 원문 `2학년 이상`을 AI가 `3학년 이상`으로 잘못 추출함.

1. 서비스가 해당 조건과 연결된 판정·색인을 보류하고 검토 요청을 만든다.
2. 내부 검토자가 공식 원문/버전/추출값/실패 사유를 본다.
3. 검토자는 **승인/수정/반려** 및 이유를 기록한다.
4. 승인·수정 후 검증된 조건을 반영하고 중단된 작업에서 재개한다.
5. 반려하면 작업 중단 및 이유를 안내한다.
6. **기관의 정책 자체가 불명확**한 경우에는 내부 검토자가 학적 적용 여부를 창작할 수 없다.

## N-01 — 새·변경 공고 알림 (별도 업무)

1. **검증에 통과한 신규·변경** 공고가 등록된다.
2. 서비스가 해당 공고와 학생 프로필을 비교한다.
3. **가능으로 판정된 학생**을 알림 대상으로 선정한다(알림 동의/전달 채널 정책은 OPEN-09).
4. 학생별 알림함 기록을 남긴다.
5. 푸시 채널을 사용한다면 성공/실패와 중복을 관리한다.
6. 학생이 들어오면 변경된 공고의 최신 상태 및 근거를 다시 확인할 수 있다.

**하지 않음:** 검증되지 않은 후보를 추천 알림으로 전송, `확인 필요`를 `가능`으로 승격, 알림 수신을 신청으로 간주.
