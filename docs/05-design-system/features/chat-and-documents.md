## 사용자 목표
장학금마다 조건/서류/문항이 달라도 **새 폼을 계속 만들지 않고**, AI가 필요한 질문을 순서대로 하고 검증 가능한 사실을 모아 초안을 준비한다.

## 3열 작업공간
- 좌측: 대화·준비 중 공고 목록 / 통합 탐색 네비게이션.
- 중앙: 대화 제목(현재 공고) → 안내 → 메시지 흐름 → Quick Reply → 입력창.
- 우측: 현재 공고·조건 판정·필요 서류·근거. 대화와 같은 공고의 정보만 표시.
- 모바일: 중앙 대화가 최우선. 우측 요약은 하단 카드 또는 '근거·진행 상태 보기' 확장 UI.

## 메시지의 상태/구성
- `assistant`: 답변, 추가 질문 이유, 출처 표기, 선택지, 다음 행동.
- `student`: 사용자가 직접 입력·선택한 답변. AI 추측으로 재작성하지 않는다.
- `loading`: 입력창 중복 제출 방지 + '답변을 정리하고 있어요'.
- `error`: 메시지 잔존 + '다시 보내기'.
- `unknown`: 확실치 않은 정보는 '모름/확인 필요'를 저장하고 다음 단계 진행 가능 여부를 구분.

## 재사용 질문 부품
`MissingInfoQuestion`은 장학금별 조건을 받아 문장/선택지를 생성한다. 화면을 장학금별로 하드코딩하지 않는다.

필수 필드: `questionId`, `fieldKey`, `reason`, `sourceConditionId`, `answerChoices`, `allowUnknown`, `allowLater`, `onAnswer`.

질문 예: `소득구간을 확인하셨나요?` → `[4구간이에요] [아직 몰라요] [확인 방법 알려줘] [나중에 답하기]`.

## 문서 초안 편집
- 상단: 문서 유형, 시연/초안 상태, 저장 상태, 버전.
- 좌측: 문항 목록 + 미확인 개수.
- 중앙: 편집 가능한 텍스트, 확인된 사실은 그대로, 모르는 정보는 자리표시자.
- 우측: 초안에 사용한 사실과 확인이 필요한 정보.
- 하단: 저장 / 내보내기 (최종 제출 버튼 금지).
- 생성 문서에는 `학생 본인 검토 필수 · 기관 사이트에서 직접 제출` 표시.

## Why: 대화형 UI 선택 이유
장학금마다 서류·자격·문항이 달라 고정 폼을 무한히 늘리기 어렵다. 대화형 질문과 구조화된 근거·체크리스트·초안 부품을 조합하면 **조건의 다양성은 데이터/질문으로**, **UI의 일관성은 디자인 시스템으로** 흡수할 수 있다.
