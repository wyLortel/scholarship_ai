# design.md — 장학금 AI 디자인 시스템 마스터

- 버전: v0.1 / 초기안
- 디자인 기준: 제공 이미지 01–17, 강의 PDF p.4–11
- SSOT: `colors.md`, `typography.md`, `spacing.md`, `components.md`, `domain-ux-rules.md`
- **이 파일은 디자인 계약**이다. 테스트 명세/TDD와 별개의 계층이다.

## 1. 제품 디자인 한 문장
학생이 공식 장학금 공고를 찾고, **확인된 사실과 미확인 사실을 구분**하면서 자격을 비교하고, 대화를 통해 부족한 정보를 채운 뒤, **직접 검토할 신청 서류 초안**을 안전하게 준비하도록 돕는다.

## 2. 디자인 원칙(우선순위)
1. **정보 신뢰성 > 장식**: 원문 근거·공고 버전·시연 여부·정보 확인 필요를 드러낸다.
2. **하나의 기본 과업**: 각 화면의 가장 중요한 다음 행동은 Primary CTA 하나로 표현한다.
3. **회원정보 재사용 + 질문 최소화**: 이미 확인된 정보는 다시 묻지 않고 미확인된 항목만 질문한다.
4. **AI는 보조자**: 자격 확정, 기관 제출, 증빙 발급, 심사 수행을 암시하지 않는다.
5. **상태는 색만으로 전달하지 않음**: 아이콘+텍스트+근거 또는 다음 행동을 함께 제공한다.
6. **일관성 > 화면별 독창성**: 새로운 버튼/여백/폰트/배지 변형을 임의로 만들지 않는다.

## 3. 시각 언어
- 밝은 `#F7F9FE` 계열 배경, 흰색 정보 카드, 진한 남색 텍스트.
- 브랜드 강조: 파란색→보라색 그라디언트. **Primary CTA와 주요 브랜드 강조에만** 사용.
- 넓은 모서리(`--radius-lg`~`--radius-xl`), 옅은 테두리, 낮은 그림자, 4px 기반 간격.
- 삽화: 학사모를 쓴 AI 로봇. Hero/온보딩/빈 상태에 제한 사용. 작은 데이터 리스트에는 아이콘 사용.
- 카드 간 시각적 균형: 제목/설명/상태/행동 순서. 반복 정보는 그룹화하고 위계를 만든다.
- 이미지는 PNG 기준. 확정 로고·벡터 소스 파일은 제공되지 않았으므로 임의로 '원본 로고'라고 주장하지 않는다.

## 4. 사용 화면 유형
- **마케팅 영역**: 비로그인 홈 / 독립 로그인.
- **온보딩**: 학적 정보 → 지역·소득·활동 정보 → 시작.
- **핵심 탐색**: 추천 결과 / 상세 조건·근거 / 자유 채팅.
- **장학금별 작업**: 조건 추가 질문 / 제출서류 안내 / AI 초안 편집.
- **관리·지속 작업**: 내 신청 준비 / 회원정보 / 알림 / 변경 재판정.
- **운영자**: 검토 큐 / 추출 조건 대조 및 승인.
- 자세한 화면별 매핑: `screen-map.md`.

## 5. 공통 레이아웃
- Desktop: max-width 1280px(권장); 가로 24–32px 안쪽 여백.
- Header: 높이 72px(제안), 브랜드 좌측, 주요 네비게이션 중앙, 계정/알림 우측.
- 메인 콘텐츠: 정보 탐색 2열(주요 콘텐츠+보조 패널); AI 대화 3열(좌측 내비+대화+오른쪽 근거·진행 상태).
- 정보 카드: 흰색, 1px 테두리, 16–20px radius; 내부 padding 20–24px.
- Mobile: 한 열 우선. 대화 입력을 화면 아래에서 쉽게 찾게 한다. 근거/요약은 접히는 상세 패널로 제공.

## 6. 상태와 문구는 공통 계약
`가능(조건상 가능)`, `확인 필요`, `불가(현재 정보 기준)`, `판정 보류(원문 검증 중)`, `모집 상태 미확인`, `공고 변경으로 재판정 필요`를 **서로 구분**한다.

**나쁜 예**: '지원 자격이 확정되었습니다', 'AI가 알아서 서류를 제출합니다', '모름 = 탈락'.
**좋은 예**: '입력된 정보 기준으로 조건상 지원 가능합니다. 모집 상태와 공식 원문을 확인하세요.'

## 7. UX의 핵심 사용자 여정
1. 홈 → Google OAuth 로그인(실제 연동 전에는 시연 전용임을 표시)
2. 기본 회원정보 기입 → 사실 입력/수정 → 명시적 저장
3. 후보 장학금 검색 → 조건별 근거와 판정 확인
4. 미확인 항목을 채팅으로 질문 → 사용자 입력의 출처/기준시점 저장
5. 서류 체크리스트 → 필요 항목 확인 → 초안 생성/수정
6. 저장된 준비 현황 → 공고가 바뀌면 이전 자격과 새 자격 비교
7. 공식 기관 사이트에서 학생이 직접 제출

## 8. 변경 관리
- 새 색/간격/폰트/컴포넌트가 필요하면 먼저 네 가지 토큰 문서 중 해당 파일을 수정.
- 새 상태가 필요하면 `domain-ux-rules.md`의 상태와 표기 규칙까지 수정.
- 컴포넌트 API 변경은 `components.md`의 목적, props, states, a11y, 적용 화면을 함께 수정.
- 스크린샷만 보고 추측해 만든 CSS는 확정 토큰이 아님. 팀 승인 전에는 `proposed` 표시.
