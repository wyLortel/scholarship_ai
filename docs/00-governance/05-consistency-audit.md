# 설계 정합성 감사 — 혼동하기 쉬운 결정을 점검

> 책임: 제공된 A/B/C 정의와 v7 기술 설계 사이의 **차이·위험·미확정 연결점**을 드러내고 팀이 무엇을 검증해야 하는지 기록한다. 제품 규칙을 새로 만들지 않는다.

| 쟁점 | 원래 정의/설계 의도 | 생기는 오류 | 이번 문서에서 취한 처리 | 후속 확인 |
|---|---|---|---|---|
| ‘지원 가능’이 선발 보장처럼 보임 | Rule Engine은 해당 공고 자격 비교만 함 | 합격 확정처럼 오해 | BR-B05, UX 문구의 ‘조건 충족’ | 학생이 실제로 이해하는지 사용자 검증 |
| UNKNOWN이 불가로 처리됨 | 모르면 질문하거나 기관 확인 | 학생의 기회를 부당하게 제거 | BR-B01/B04, AND/OR 표, AC-B01 | 빈값·숫자 0·null 단위 테스트 |
| 공고의 검증과 최신성을 합쳐버림 | A는 공식성·변경·조건 검증을 각각 판단 | 이전/미검증 원문을 최신으로 공개 | 세 상태 축 + versioning 문서 | 실제 크롤러 구현·실패 처리 검사 |
| 학생이 미확인 정보를 남겨도 준비 완료 | v6가 허용한 업무 | 준비 완료=자격 확정 오인 | `PREPARED_WITH_OPEN_ITEMS` 제안 | OPEN-16: 허용/경고/중단 경계 팀 결정 |
| 내부 검토자가 기관 규정까지 결정 | 원문 추출 오류를 승인/수정/반려 | 휴학생 포함 여부를 임의 확정 | decision-boundaries, D4, BR-O03 | 운영자 실제 역할·기관 문의 규칙 |
| 학생 서류 vs 작성 초안 혼동 | v6 이후 증빙 업로드·보관 제외 | 민감한 학생 증빙 저장 | BR-C08, ADR-0012, C 계약 | 현재 UI/API에 업로드 기능이 있는지 확인 |
| Agent Server의 실행 상태 vs 업무 상태 혼동 | v7은 체크포인트와 업무 DB를 분리 | 재부팅 시 답변이나 결과 분실 | state-machines/agent-workflow | Worker crash/resume PoC |
| Outbox가 모든 문제 해결한다고 착각 | v7은 재정합성 검사 추가 | delivered 후 Redis/run 손실 | failure-boundaries, ADR-0005 | 큐 재정합성 실제 코드 시험 |
| Agent Server 2개니까 HA 달성 | v7은 EC2 단일 호스트 | EC2 장애 때 모든 작업 중단 | ADR-0008과 architecture 설명 | 교수님 목표 장애 수준/부하 수치 |
| 새·변경 공고 알림이 자동 선정으로 보임 | 검증된 새·변경 & 가능 학생만 | UNKNOWN/불가 학생에게 오발송 | BR-N01, AC-N01 | 수신 동의·FCM 정책 OPEN-09 |
| 사업과 구현 우선순위 혼동 | 목표는 A/B/C 전체 | 첫 시연에 일부만 해서 목표 자체 삭제 | PRD 전체 FR 유지, R1~R3 ‘제안’ | 교수님 시연 필수 항목 최종 합의 |
| 로컬 랩 구현 주장 vs 코드 검증 | v7은 로컬 일부 ‘구현 완료’라고 기술 | 테스트 안 했는데 성공이라고 발표 | `SOURCE-CLAIM` 별도 | 실제 레포·CI·데모 검사 |

## 이 문서로 Claude를 검증하는 질문

1. 소득구간을 모르는 3학년과, 1학년에 소득구간 모르는 학생에게 결과가 왜 다른지 설명할 수 있는가?
2. 공식 출처 확인 완료·조건 검증 완료·최신 확인 완료는 왜 서로 다른가?
3. AI가 ‘2학년 이상’을 ‘3학년 이상’으로 잘못 읽으면 검증 전/후 어떤 상태가 바뀌는가?
4. `PREPARED_WITH_OPEN_ITEMS`의 의미는 무엇이며 어떻게 `SUBMITTED`와 다른가?
5. 변경 공고 알림에서 왜 `NEEDS_REVIEW`를 발송 대상에서 제외하는가?
6. Agent Server의 Checkpoint가 왜 비즈니스 DB의 PreparationCase를 대체하지 못하는가?
7. 단일 EC2에 컨테이너 8개가 있어도 왜 완전한 고가용성은 아닌가?
8. 비공식 뉴스에서 기관을 발견했을 때 공식 공고 목록에 즉시 추가해도 되는가?

이 질문에 코드·시스템이 답하지 못하면 **문서를 더 늘리는 것보다 테스트와 정책 결정을 먼저 보강해야 한다**.
