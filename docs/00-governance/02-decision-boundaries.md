# 결정 권한과 경계

> 책임: **누가 결정하는가**. 도메인 규칙 또는 기술 기능을 여기서 다시 정의하지 않는다.

| 판단 | 결정권/출처 | 시스템 역할 | 하면 안 되는 일 |
|---|---|---|---|
| 모집 자격·예외 규정의 의미 | 최신 공식 기관 공고·기관 담당자 | 근거를 표시하고 평가 가능한 부분만 적용 | LLM·서비스 관리자가 규정을 독자 확정 |
| 학생의 본인 정보 | 학생, 필요한 경우 외부 기관 증빙 | 학생이 제공한 값과 미확인 값을 구분 | 모르는 값을 임의 생성·공식 증명으로 표시 |
| 추출한 문장·조건의 정합성 | 내부 검토자 | 원문 위치와 후보 추출값을 비교해 수정/승인/반려 | 기관의 장학생 선발을 승인하는 듯 표현 |
| 전체 판정 결과 | Rule Engine + 검증된 조건/학생 값 | 결정된 판정값 표시, 이유 설명 | LLM의 새로운 문장으로 판정 변경 |
| 실제 신청 접수·선발·지급 | 외부 장학금 기관 | 공식 사이트 링크·진행 방법 안내 | 자동 제출, 합격/지급 확정 표시 |
| 제품 범위·우선순위 | 프로젝트 팀 | PRD 승인, 사용자 검증 | 코드에 기능을 추가한 사실을 곧 제품 승인으로 간주 |
| 스택·운영·투자·위험 수용 | 프로젝트 팀/지도교수 합의 | ADR로 대안·비용·검증 기록 | Claude가 라이선스/성능 추측 후 도입 |

### 역할 충돌 사례

**예: ‘재학생’의 의미가 휴학생을 포함하는지 모름** → 원문으로 구분할 수 없으면 기관 확인 필요. 관리자가 임의로 “포함” 승인하지 않는다.

**예: 원문은 ‘2학년 이상’, LLM이 ‘3학년 이상’ 추출** → 운영자는 원문 대조 후 추출값을 수정할 수 있다. 이것은 기관의 정책을 바꾼 것이 아니라 **전사 오류를 수정한 것**이다.
