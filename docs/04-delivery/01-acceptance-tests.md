# 도메인 수용 테스트 — Given / When / Then

> 책임: 문서가 주장하는 업무가 실제 구현에서 **어떻게 검증되는지**. 여기 적힌 것은 **실행 계획**이며 현재 통과 증거가 아니다. ID를 PRD·BR·코드 테스트 이름에 그대로 사용한다.
>
> **AC 정의와 FR↔AC 연결의 유일 원본은 이 문서다.** 각 AC의 `연결:` 줄이 그 AC가 검증하는 BR·FR이다. PRD 등 다른 문서는 AC를 재서술하지 않고 ID만 인용한다. `tools/check_pack.py`가 ID 존재·중복·FR 커버리지를 검사하지만 **연결의 의미가 맞는지는 사람이 검토**한다.

## A. 공고 수집·검증

### AC-A01 출처 후보는 공식 확인 이전에 신뢰할 수 없다
- **Given** 뉴스에서 새로운 장학금 기관 링크를 발견했다(아직 공식성 검증 안 됨).
- **When** 추천 목록을 조회한다.
- **Then** 출처 후보만으로 해당 기관의 장학금을 공식 검증 공고로 노출하지 않는다. 후보는 검토함에 남긴다.
- 연결: BR-A01, BR-A02, FR-A01.

### AC-A02 신규/변경/변경없음과 실패 구별
- **Given** 동일 공고가 v1 해시로 저장된 상태.
- **When** (1) 새로운 회차, (2) 바뀐 원문, (3) 동일 원문, (4) 사이트 타임아웃으로 수집한다.
- **Then** 각각 `NEW / CHANGED / UNCHANGED / CHECK_FAILED`로 취급하며 (2)는 v2 스냅샷 생성, (3)은 재분석 없음, (4)는 `변경 없음` 아님.
- 연결: BR-A03, BR-A04, BR-A09, FR-A02.

### AC-A03 잘못 추출된 규칙 공개 차단
- **Given** 가상 원문 `2학년 이상`, 후보 추출 `3학년 이상`.
- **When** 검증한다.
- **Then** 후보를 검증된 RuleSet/검색 인덱스로 공개하지 않고 재추출 또는 내부 검토 요청을 만든다.
- 연결: BR-A05, BR-A06, FR-A03.

### AC-A04 공식 버전과 벡터 검색
- **Given** `유사도 높은` 비공식 문장과 `유사도 낮은` 공식 원문이 있다.
- **When** 조건을 설명한다.
- **Then** 모델은 비공식 문장을 근거로 쓰지 않고 승인된 공식 원문 위치를 제공하거나 확인 필요 표시.
- 연결: BR-A07, FR-A03.

## B. 자격 판정·추천

### AC-B01 모름은 FAIL이 아님
- Given: 검증된 시험 공고 필수조건 `학년 >= 2 AND 소득구간 <= 5`, 학생 `3학년`, `소득구간 모름`.
- When: 평가.
- Then: 학년 PASS, 소득 UNKNOWN, 전체 NEEDS_REVIEW. 모름을 `0`으로 계산/비충족 취급 금지.
- 연결: BR-B01, BR-B04, FR-B01, FR-B02.

### AC-B02 확정 FAIL과 UNKNOWN 동시 존재
- Given: 같은 시험 공고, 학생 `1학년`, `소득 모름`.
- When: 평가.
- Then: 학년 FAIL, 소득 UNKNOWN, 전체 INELIGIBLE. **실패 조건과 원문 근거가 있어야 함**.
- 연결: BR-B03, BR-B06, FR-B02, FR-B03.

### AC-B03 모두 PASS
- Given: 같은 시험 공고, 학생 `3학년`, `소득 4`.
- When: 평가.
- Then: 전체 ELIGIBLE, ‘기관 최종 선발 별도’ 표현, 버전·평가 스냅샷/근거 표시.
- 연결: BR-B05, BR-B06, FR-B02, FR-B03.

### AC-B04 OR 및 괄호 보존
- Given: 검증된 규칙 `A AND (B OR C)`에서 A=PASS, B=FAIL, C=PASS.
- When: 평가.
- Then: PASS. 조건을 무작정 `A AND B AND C`로 펼쳐 FAIL 반환하면 안 됨.
- 연결: BR-B08, FR-B02.

### AC-B05 빈/미검증 규칙으로 가능 금지
- Given: 원문 분석 실패 또는 규칙 트리 누락.
- When: 평가.
- Then: `ELIGIBLE` 금지. `NEEDS_REVIEW`/검토 중과 사유 표시.
- 연결: BR-B09, FR-B02.

### AC-B06 설명 모델이 판정을 뒤집을 수 없음
- Given: Rule Engine 결과 `INELIGIBLE`.
- When: LLM이 '가능해 보인다'라고 응답.
- Then: API 최종 결과는 INELIGIBLE 유지, 안전한 설명 재생성 또는 오류.
- 연결: BR-B02, FR-B02.

### AC-B07 구버전 근거 무효
- Given: v1 평가 ELIGIBLE, v2가 새로 검증되고 해당 조건이 더 엄격해짐.
- When: 학생이 상세를 연다.
- Then: v1 평가를 최신이라고 표시하지 않고 v2 기준 재판정/`stale` 표시.
- 연결: BR-A08, BR-B06, FR-B04.

### AC-B08 확정 FAIL만 있는 경우
- Given: 같은 시험 공고, 학생 `3학년`, `소득구간 7`.
- When: 평가.
- Then: 학년 PASS, 소득 FAIL, 전체 INELIGIBLE. 실패한 소득 조건과 원문 근거 표시.
- 연결: BR-B03, BR-B06, FR-B02.

### AC-B09 근거가 연결되지 않은 결과는 '검증 완료'로 표시하지 않음
- Given: 조건별 결과 중 원문 근거(`evidence_ref`)·공고 버전·확인 시각 중 하나가 비어 있다.
- When: 결과 상세를 조회한다.
- Then: 해당 결과를 '근거 검증 완료'로 표시하지 않고 누락된 근거 항목을 드러낸다.
- 연결: BR-B06, FR-B04.

### AC-B10 같은 입력이면 같은 구조화 결과
- Given: 같은 `rule_set_id`·학생 사실 스냅샷·평가 기준 시각.
- When: 두 번 평가한다.
- Then: 조건별 결과와 전체 그룹이 동일하다(설명 문구는 달라도 됨). UNKNOWN을 0/FAIL로 바꾸지 않는다.
- 연결: BR-B01, BR-B02, FR-B02.

## C. 신청 준비

### AC-C01 시작 전 최신 확인 실패
- Given: v1 `가능`, 공식 사이트 확인 timeout.
- When: 준비 시작.
- Then: `최신 확인 실패`와 마지막 성공 확인 시각을 표시. 자동으로 변경 없음/가능 확정 아님.
- 연결: BR-C01, BR-C09, FR-C01.

### AC-C02 변경 공고에서 불가
- Given: v1 가능, v2의 새 필수조건에서 확정 FAIL.
- When: 준비 상태 검토.
- Then: 준비 중단/근거·바뀐 조건 표시. 이전 초안 최신으로 표기하지 않음.
- 연결: BR-A08, BR-C02, FR-C01.

### AC-C03 질문/복귀
- Given: 소득구간 UNKNOWN으로 `WAITING_STUDENT`인 준비 건 X.
- When: 새로고침 후 같은 사용자로 로그인해 답변 제출.
- Then: 같은 X의 이전 입력·대기 질문을 복원하고 답변 적용 후 재평가. 질문 이중 제출에도 논리적 업데이트는 한 번.
- 연결: BR-C03, FR-C02.

### AC-C04 답변 불가→기관 확인 필요
- Given: 공고의 '재학생' 규정이 휴학 중 학생에 적용되는지 원문 자체가 불명확.
- When: 학생이 휴학 중임을 알림.
- Then: `기관 확인 필요`, 문의 경로/확인할 질문 표시. FAIL이나 PASS 창작 금지.
- 연결: BR-C04, BR-O03, FR-C02.

### AC-C05 체크리스트/개인 서류 범위
- Given: 가상 공고에서 발급받아야 할 재학증명서가 명시됨.
- When: 준비 체크리스트 표시.
- Then: 서류명·공식 근거·발급 안내 표시, 개인 재학증명서 업로드를 요구하지 않음.
- 연결: BR-C05, BR-C08, FR-C03.

### AC-C06 초안의 사실성
- Given: 사용자가 멘토링 활동 두 회만 입력하고 수상 이력은 미제공.
- When: 자기소개서 초안 생성.
- Then: 미제공 수상·성적·소득/경력을 생성하지 않음. 해당 질문에 필요한 미확인 사실은 플레이스홀더/질문.
- 연결: BR-C06, FR-C04.

### AC-C07 서비스 준비 완료와 공식 제출
- Given: 초안을 다운받고 체크리스트 확인.
- When: 외부 제출 링크 클릭.
- Then: 서비스의 `PREPARED`만 표시. 기관 제출 성공 여부는 자동 확정하지 않음.
- 연결: BR-C07, FR-C05.

## D. 내부 검토/알림

### AC-D04 관리자 수정 후 재개
- Given: 원문 2학년 이상, 추출 3학년 이상으로 검토 대기.
- When: 권한 있는 검토자가 원문에 맞춰 `2학년 이상`으로 수정+사유 입력.
- Then: 결정 이력/버전 저장, 해당 검증된 조건으로 중단 흐름 재개, 수정 전 계산값 최신 표시 금지.
- 연결: BR-O01, BR-O02, FR-A04.

### AC-D05 관리자 반려
- Given: 수집 원문 확인 실패나 임의로 정책 해석할 수 없는 경우.
- When: 검토자가 반려.
- Then: 재개하지 않고 실패·문의 필요 표시; 기관 선발을 반려했다고 주장하지 않음.
- 연결: BR-O02, BR-O03, FR-A04.

### AC-N01 검증된 새 공고의 가능 학생에게만 알림
- Given: 신규 v1, 해당 학생 중 A=가능/B=확인 필요/C=불가.
- When: 알림 대상 계산.
- Then: A만 가능 대상으로 선정, B/C 제외. 사용자별 알림함 기록. 푸시 동의 정책이 미확정이면 실푸시는 발송하지 않음.
- 연결: BR-N01, BR-N03, FR-N01.
